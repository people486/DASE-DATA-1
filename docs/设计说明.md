# 系统与数据库设计说明

## 系统说明

系统支持注册登录、本人问卷管理、发布截止关闭、链接填写、四类题型、条件跳转、答案校验及结果统计。前端为原生HTML CSS JavaScript，后端使用Python标准库HTTP服务及PyMongo，全部业务数据存储在MongoDB，不使用关系数据库或现成问卷系统框架。

请求依次经过app.py接口层、service.py业务层、logic.py规则层和MongoDB。规则层不依赖HTTP或数据库，便于第二阶段在现有代码基础上增加题型与规则。运行配置与步骤见仓库根目录README.md。

## MongoDB集合

|集合|字段与结构|用途|
|---|---|---|
|users|_id、username、password_hash、created_at|账号，密码存随机盐加PBKDF2摘要|
|sessions|_id为token摘要、user_id、expires_at|登录认证和过期控制|
|surveys|owner_id、title、description、allow_anonymous、allow_repeat、deadline、status、questions、created_at、schema_version、revision|问卷设置、题目和跳转规则|
|responses|survey_id、survey_revision、schema_version、answers、path、submitted_at、anonymous、submitter_key、request_id；按情况保存user_id及dedupe_key|每次填写的独立答卷|

题目以questions数组嵌入问卷，包含id、title、type、required、validation和rules，选择题增加options。答案answers为题目ID到字符串、数组或数值的映射，path记录实际答题顺序。时间字段存为MongoDB日期，题目顺序由数组确定。

题目通常整份读取、规模有限，嵌入可以保持题目、顺序和规则一起更新；答卷持续增加，独立集合避免问卷文档无限膨胀和大量提交争用同一文档。不是把MongoDB机械拆成关系表，也不是把全部数据塞入一个集合。关系数据库可以实现问卷业务，但本项目使用文档嵌套表达不同题型和校验规则。

不在每份答卷里复制问卷标题和全部选项，不重复存储累计统计；保留修订号和路径解释历史记录。数字以数值保存，统计实时从合法答卷计算。

## schema与索引

具体MongoDB $jsonSchema验证器和索引在survey/storage.py，initialize可以重复执行。

|集合|索引|用途|
|---|---|---|
|users|username唯一|用户名不可重复|
|sessions|expires_at TTL|清理过期会话，认证时还显式检查过期时间|
|surveys|owner_id与created_at|本人问卷列表|
|responses|survey_id与submitted_at|答卷查询|
|responses|survey_id与request_id唯一|同次请求重试不重复入库|
|responses|survey_id与dedupe_key部分唯一|禁止同账号重复，允许重复时省略dedupe_key|

数据库验证器限制关键字段和类型，业务层检查题目、规则和答案之间的关系。两层配合，唯一索引承担并发写入时的最终约束。

## 关键业务逻辑

问卷状态为draft到published到closed。只允许草稿编辑，保存携带revision并做条件更新，防止覆盖别人的新修改。发布后冻结题目，答卷保存survey_revision。第二阶段如需发布后修改，须增加完整版本快照，不能只更改修订号。

单选跳转使用eq；多选使用contains_any或contains_all；数字使用eq、gt、gte、lt、lte。规则按数组顺序首次匹配生效，没有匹配时进入下一题。目标题只能在当前题之后或为END，防止回跳循环。

填写者须登录，next接口检查当前答案，提交时再从第一题重算实际路径，只验证经过的题；额外提交未知题或跳过题会拒绝。被跳过的必答题不构成漏答。数字0合法，布尔值不能伪装成数字，数字必须有限，多选不允许重复选项，选填题空值可省略。

匿名表示不向问卷作者展示账号。匿名答卷不保存user_id，仍保留每问卷的身份摘要控制重复；这不是对数据库管理员不可关联的强匿名。账号不可以通过切换匿名和实名绕过防重。

作者权限按owner_id检查，未登录不可填写；草稿、关闭或已截止问卷不可提交。统计仅作者可见，选择题按答卷计次数，填空保留全部有效内容，数字平均值不包含跳过和空答案；无数据时平均值为null。详见API说明.md。

## 第一阶段交互与统计改进

编辑器通过题型、范围、选项和目标下拉框生成原有questions/rules结构；规则可上下排序，只提供后续题或END。高级JSON仍可用。删除题目时列出引用它的题，并在确认后清理指向它的规则；后端继续拒绝悬空引用。

草稿设置与题目统一携带revision保存。未保存状态显示在页面，离开页面有提示；题目表单先应用到本地草稿，再保存到数据库。发布前预览复用validate_answer、next_id和validate_submission，预览接口只构造副本，不写数据库。已发布题目仍冻结，旧记录结构不变，schema_version保持1，无需迁移。

统计不再把全部答卷取回Python遍历，而在MongoDB按survey_id筛选，通过$getField读取答案，$group计数与求平均，选择题先$unwind，填空内容按submitted_at及_id稳定排序、跳过并限制条数。平均值始终在分页前计算。API保留旧指标名称，values改成分页返回并增加分页元信息，调用方需按has_more取后续页。

此次验证包括23组真实MongoDB及HTTP自动测试，以及独立测试库内的实际浏览器注册、建题、三类规则配置、预览、发布、填写、错误提示、匿名提交、统计筛选与分页。测试细节见测试用例；这些记录由AI实际执行，不标为学生手工操作。
